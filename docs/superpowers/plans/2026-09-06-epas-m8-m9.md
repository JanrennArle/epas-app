# EPAS Modules 8 and 9: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The last two modules. A student maps an audio system's signal path and finds a dead channel, identifies the boards inside a television and diagnoses a picture that will not light, reads a control board, and finds why a motor will not stop.

**Architecture:** No new engines and no new components. Every format this plan needs already exists: hotspot, match, sequence, troubleshooter. This plan is three activity data files, three fault scenario data files, and two content modules. That is the payoff for building the formats generically.

**Tech Stack:** Existing only. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-06-epas-learning-app-design.md`
**Visual authority:** `docs/DESIGN.md`
**Deferred items:** `docs/superpowers/plans/CARRY-FORWARD.md`
**Reference implementations:** `src/content/activities/flat-iron-parts.ts` for a hotspot diagram, `src/content/activities/cctv-signal.ts` for a chain, `src/content/scenarios/fas-zone.ts` for a scenario, `src/content/m7.ts` for module style. Read all four before starting.

## Global Constraints

- **No new dependencies.** None, for any reason.
- **No CDN, no external runtime asset.**
- **SVG only, authored as typed shape data. No `dangerouslySetInnerHTML`.**
- **No drag and drop.**
- **`--danger` is reserved for safety hazards.** Wrong answers use `var(--caution)`.
- **Radius:** cards and tiles 14px, controls 10px, pills full.
- **Motion:** only `transform` and `opacity`, only the existing `.tile` press.
- **Touch targets 44px minimum.**
- **No em dashes, no emoji** in any user-visible string.
- **Only `src/lib/store.ts` touches localStorage.**
- **New modules ship `teacherReviewed: false`.**
- **Competency strings are quoted verbatim** from `docs/reference/G12-TechPro-EPAS-budget-of-work.txt`. **The source is inconsistent and those inconsistencies must be preserved.** In Module 8 specifically, competency 2 reads **"Perform procedure in servicing audio products and systems."** with no "the", where every Module 9 equivalent reads "Perform the procedure in servicing ...". Both are correct as written.
- Compiles under `strict`, `noUnusedLocals`, `noUnusedParameters`, `noUncheckedIndexedAccess`.

## Carried forward, and how this plan handles it

From `CARRY-FORWARD.md` and prior ledgers. Task 2 must honour all five:

1. **Every non-implicating test point needs a `'*'` reading.** A missing one renders blank, silently.
2. **Safety lines must be distinct strings** within a scenario.
3. **Test points are authored in service order,** because `requiredTests` returns the position of the last implicating one.
4. **Fault labels are lower-cased mid-sentence.** Capitalise the first letter, and never begin a label with an acronym, because "the fault was the hdmi board" is nonsense.
5. **A `'*'` reading is written for the decoys that actually occur.** If anyone later changes a scenario's `actualFault`, every `'*'` must be re-checked.

New in this plan, and the reason Task 1 needs care: **hotspot regions must not overlap at phone width.** The buttons are 44 by 44 and the diagram renders at a minimum of 400 CSS pixels wide, so any two regions closer than 44 units in BOTH axes will overlap and the later one will steal the tap. Task 1 step 4 checks every pair.

**Note on the torch test.** It is the only test point in the project that implicates two faults, and that is deliberate: a torch tells you the panel is being driven but not lit, which narrows the fault to the backlight or to the glass, and the two are told apart by what the torch shows. `requiredTests` counts the LAST implicating position, so for `backlight` that is position 3, the driver measurement. A student who runs standby, torch and driver scores full marks.
